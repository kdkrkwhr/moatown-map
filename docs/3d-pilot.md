# 모아타운 3D 시범 작업 지시서

대상지 상세의 `3D 보기`에서 같은 위치의 기존 건물과 사업 계획을 비교한다. GitHub Pages에서 선택한 대상지의 정적 파일만 읽는다. 시범 대상은 아래 세 곳이며, 표의 내용은 2026.11.24 스냅샷을 기준으로 한다. [스냅샷 명세](../moatown-data/latest.json)

| 대상지 | 검증할 사례 |
| --- | --- |
| [양천구 신월동 102-33](https://kdkrkwhr.github.io/moatown-map/?town=mt-202603-public-067) | A1~A4의 참고 경계를 표시한다. 대상지 관리계획과 A1 후속 통합심의의 적용 범위·기준일을 대조한다. |
| [강북구 번동 429-114](https://kdkrkwhr.github.io/moatown-map/?town=mt-202603-public-034) | 1~5구역의 사업개요를 이용한다. 번동1구역의 28층·80m와 4구역의 35층·100m를 각각 선택해 근거를 확인할 수 있어야 한다. |
| [중랑구 면목동 86-3](https://kdkrkwhr.github.io/moatown-map/?town=mt-202603-public-010) | 면목역 1·2구역에는 계획 층수·높이가 있고 4·6구역에는 해당 수치가 비어 있다. 같은 화면에서 확인된 값과 ‘미확인’을 구분한다. |

## 기존 건물 수집과 노후도 계산

1. VWorld의 GIS건물통합정보 API나 국토교통부의 서울 지역 SHP에서 건물 도형과 속성을 읽는다. 표제부로 보충할 때는 건물 식별자와 해당 동을 대조한다. 같은 지번에 여러 동이 있고 연결이 불명확하면 해당 속성은 `null`로 남긴다. 데이터셋명, 출처 URL, 원자료 기준일, 이용 조건과 실제 사용한 컬럼을 기록한다. 서울 전체 원본은 작업 환경에서만 처리한다. [GIS건물통합정보](https://www.data.go.kr/data/15083092/fileData.do) · [건축물대장정보](https://www.data.go.kr/data/15134735/openapi.do)
2. 미터 단위 투영좌표계에서 대상지 참고 외곽을 150m 확장한다. 이 범위의 BBOX로 후보를 조회한 뒤 실제 확장 도형과 교차하는 건물을 선택하고, 각 건물의 외곽선 전체를 보존한다. 원래 대상지에 들어가는 건물은 ‘내부’, 안팎에 걸치면 ‘경계 걸침’, 나머지는 ‘주변’으로 구분한다. 참고 외곽이 없는 대상지의 내부 판정과 노후도 통계는 보류한다.
3. 저장 시 WGS84 경도·위도 순서로 변환하고 소수점 6자리로 반올림한다. 반올림 후에도 폴리곤의 링과 구멍이 유효한지 검사한다. 위치 정확도는 원본 도형의 출처·작성 방법으로 설명한다. [GeoJSON 좌표 표기](https://www.rfc-editor.org/rfc/rfc7946#section-3.1.10)
4. 건물마다 고유 ID, 사용승인연도, 지상층수, 높이(m), 높이 근거를 둔다. 양수인 공식 높이는 `official`, 높이가 비고 유효한 지상층수가 있으면 `층수 × 3.0m`와 `estimated_from_floors`를 기록한다. 후자는 화면에서 ‘층수 환산 높이’로 표시한다. 둘 다 미확인이면 높이와 근거는 `null`이며 평면 외곽선으로 표시한다.
5. 건물 연령은 스냅샷 기준연도에서 사용승인연도를 빼서 30년 이상, 20~29년, 20년 미만, 미확인으로 분류한다. ‘30년 이상 건물 비율’의 분모는 **내부 건물 중 사용승인연도가 확인된 고유 건물 수**다. 분자·분모와 연도 미확인 동 수를 함께 표시한다. 분모가 0이면 ‘산정 불가’로 표시한다. 경계 걸침과 주변 건물은 따로 집계한다.

GeoJSON의 건물 속성은 `id`, `approval_year`, `age_years`, `age_tier`, `floors`, `height_m`, `height_source`, `is_inside_town`을 사용한다. `age_tier` 값은 각각 `30_plus`, `20_to_29`, `under_20`, `unknown`이다. 참고 외곽을 확보한 대상지에서 `is_inside_town`은 내부이면 `true`, 주변이면 `false`, 경계에 걸치면 `null`이다.

## 사업 계획 수치와 근거

관리계획 공람·승인 및 후속 사업 단계의 고시문, 공람문, 통합심의 자료를 대상지명·지번·구역번호와 ‘최고 층수’, ‘높이’, ‘용적률’로 찾아 대조한다. 대상지 기록은 `towns`, 개별 구역 기록은 `zones`에 둔다. 3D 화면은 기존 `max_floors_above_ground`, `height_m`, `floor_area_ratio_pct`를 우선 읽고, `plan_3d`가 필요하면 같은 근거에서 표시값을 파생한다. [기존 수집 근거](data-sources.md)

| 수치마다 기록할 근거 | 원문과 대조할 사항 |
| --- | --- |
| 문서와 시점 | 공람안·승인고시·통합심의·사업시행인가·도급계약 등 문서의 성격, 발행기관, 원문 URL, 고시번호와 쪽수(해당 시), 원자료 기준일과 확인일을 기록한다. |
| 적용 범위 | 대상지 전체, 특정 세부구역, 개별 건물 동 또는 계약 범위 중 어디에 적용되는지 식별한다. 면목본동 3구역의 계약 범위에 적힌 15층은 도급계약 수치로 표시하고, 승인 최고 층수는 별도 승인 근거가 있을 때 채운다. |
| 값의 의미와 변경 이력 | ‘최고’, ‘이하’, ‘약’, 용적률의 기준·허용·계획 구분을 보존한다. 후속 자료에서 변경한 필드와 적용 구역만 갱신하고 이전 값의 근거를 남긴다. |

계획 층수만 확인되면 ‘최고 25층’처럼 원문의 표현을 쓰고 계획 높이(m)는 `null`로 둔다. 구역 단위 자료는 참고 경계와 수치 라벨로 보여준다. 개별 동의 배치 도형과 높이가 함께 확인된 곳부터 그 동을 입체로 그린다.

## 배포 파일과 무결성 검사

- 기본 파일은 `moatown-data/buildings/{townId}.geojson`이다. 압축 전 UTF-8 기준 **파일당 500KB(500,000바이트) 이하**로 저장한다. 초과하면 건물 단위로 여러 파일에 나누고 파일 목록을 기록한다. 건물 하나의 전체 도형은 같은 파일에 둔다. 보고서에는 원본 파일 크기와 압축 전송 크기를 구분한다.
- 각 스냅샷에 건물 파일 목록, 참고 외곽, 대상지·세부구역 계획 파일의 경로와 버전 또는 콘텐츠 해시를 함께 기록한다. 같은 스냅샷의 조합을 검증한 뒤 `latest.json`에서 참조한다. 화면에는 건물 원자료 기준일과 계획 원문 기준일을 각각 표시한다. 기준일이 없으면 ‘기준일 미확인’으로 표시한다.
- API는 마지막 페이지까지 받은 후 제공처가 제공하는 총건수 또는 종료 표식으로 전량 수신을 확인한다. 그다음 **원본에서 실제 공간 조건을 통과한 고유 건물 ID 집합**과 **배포 파일 전체의 ID 집합**이 같은지 대상지별로 검사한다. 분할 파일 안팎의 중복 ID도 검사한다. 누락·중복·도형 오류가 있으면 해당 ID와 사유를 검수 목록에 남기고 재검증한다.

## 모바일 확인과 시범 산출물

1. 네이버 지도에서 대상지와 세부구역을 선택한 채 `3D 보기`를 연다. ‘현재 건물’과 ‘사업 계획’을 전환해도 선택 구역과 중심·방향·기울기·확대 수준을 유지한다. 신월동 A2를 선택해 화면을 돌리고 확대한 뒤 두 모드를 왕복해 검증한다.
2. 뷰어의 뒤로 버튼과 모바일 브라우저 뒤로 가기를 각각 확인한다. 둘 다 진입 직전의 네이버 지도 위치·확대 수준, 검색 조건, 선택한 대상지·세부구역과 상세 패널 상태로 돌아와야 한다.
3. 대상지별로 파일 목록·용량, 고유 건물 수, 대장 연결률·공식 높이 확보율(분자/분모), 환산 높이 및 높이 미확인 건수, 30년 이상 비율을 보고한다. 계획 층수·높이·용적률의 확보 건수와 보류 사유를 대상지·세부구역 단위로 구분한다.
4. `node --test` 결과와 모바일 실측 조건(기기·네트워크), 첫 진입부터 조작 가능한 시점까지의 시간을 기록한다. 세 곳의 검수 결과와 보류 목록을 바탕으로 다음 대상지로 확대할 범위를 결정한다.
