01 / CONCEPT

왜 만드는가

주민이 알고 싶은 건 “우리 동네가 어디에 속하고, 지금 어디까지 왔는가”입니다. 지역별 자료를 개별적으로 찾아야 할 때, 전체 대상지와 그 안의 사업구역을 구분하고 최신 계획의 근거를 비교하기 어렵습니다. 이 서비스는 자료를 대신 확정하지 않고, 지도에서 찾기 쉬운 형태로 연결합니다.

주 타겟 · 해당 지역 주민과 소유주

관심 지역이 대상인지, 내가 관심 있는 세부 구역의 경계와 사업 단계는 무엇인지 확인합니다.

보조 타겟 · 서울시 전역을 보는 일반 이용자

자치구별 공식 선정 대상지를 찾고, 여러 구역의 공개 계획을 살펴봅니다.

서비스 범위: 서울 전역을 대상으로 하되, 신청만 한 지역은 표시하지 않습니다. 공식 선정은 관리계획 승인이나 착공 확정을 뜻하지 않습니다. 서울시 정책 소개
02 / NAVIGATION

메뉴와 기능

지도 기본 화면
서울 전역에서 시작합니다. 자치구·단계로 좁히고, 대상지를 선택하면 경계와 내부 사업구역을 표시합니다.
대상지·구역 검색
자치구, 주소, 구역명과 사업 단계를 조합해 검색합니다. ‘강북구 착공’은 일치하는 세부 구역, ‘관리계획 승인’은 해당 대상지를 보여줍니다. 두 단계 필터를 함께 쓰거나 검색 결과 주소를 공유할 수 있습니다.
자료 안내
선정 대상 기준, 경계·진행 단계 읽는 법, 갱신일과 공식 자료 기준일의 차이를 설명합니다. 서울시·자치구 고시 등 참고 출처를 연결합니다.
구역 상세 하위 화면
지도나 목록에서 대상을 선택해 엽니다. 메뉴를 따로 늘리지 않고, 현재 보는 대상지와 사업구역을 구분해 표시합니다.

‘주소 위치 확인’에서 마포구 지번의 대표점을 참고 외곽과 대조합니다. 도로명주소는 카카오 주소 찾기에서 지번을 선택할 수 있습니다. 법정 구역 포함 여부는 관할 기관의 고시에서 확인합니다.

03 / MAP EXPERIENCE

경계부터 보이고, 상세는 선택해서

서울 전체자치구·단계 필터모아타운 선택세부 사업구역 상세
  • 서울 전체 축소 상태에서는 자치구별 수록 대상지 수를 표시합니다. 단계를 선택하면 일치하는 대상지나 사업구역의 참고 외곽에 맞춰 지도를 이동합니다.
  • 모아타운 확대: 전체 외곽선은 굵게, 세부 사업구역은 별도 경계선과 공식 명칭으로 구분합니다. 경계가 미확인인 곳은 확인된 대표 위치만 쓰거나 목록에만 둡니다. 초안 경계는 점선과 라벨로 구분합니다.
  • 선택 상태: 선택된 구역은 테두리를 강조합니다. 색만으로 상태를 알리지 않고 이름·단계 라벨과 범례를 함께 씁니다. 모바일은 하단 상세 패널, 큰 화면은 사이드 패널을 기본으로 합니다.
  • 진행 단계: 모아타운 관리계획과 세부 사업구역의 조합·사업 추진 상태를 별개로 표시합니다. 하나의 진행률이나 자동 완공 예상일로 환산하지 않습니다. 서울시 모아통합기획 발표에서도 관리계획과 조합설립의 병행 추진을 설명합니다.

상세 정보 표기 원칙

세대수·층수
세대수는 공식 자료의 구역별 총 세대수, 층수는 최고 지상 층수를 씁니다. 범위만 공개된 경우 범위 그대로 표기합니다.
주택형·시공사
주택형은 전용면적 ㎡를 우선 표기하고, 평형명은 출처에 있으면 병기합니다. 시공사는 공식 선정이 확인된 경우에만 선정으로 표시합니다.
근거와 상태
각 값에 적용 구역, 기준일과 원문을 연결합니다. 계획안·확정·미확인을 구분하고, 원문에 명시된 미선정과 단순 미확인은 다르게 표시합니다. 상위 대상지 수치를 세부 구역에 대신 넣지 않습니다.

구역을 고른 뒤 무엇을 알 수 있나

지도의 작은 팝업은 구역 이름과 최근 확인 단계를 보여줍니다. 숫자의 의미와 기준일은 상세 패널에서 읽고, 관심 있는 주택형은 펼쳐서 확인하는 구성을 목표로 합니다.

누가 짓나
시공사명 옆에 수주 발표일 또는 공사계약일을 표시합니다. 번동 1~5구역은 코오롱글로벌의 수주 발표, 면목본동 2·3·5구역은 HS화성의 공사계약 공시를 근거로 삼았습니다.
어떤 집이 들어오나
인가 당시 전체 세대수, 일반분양·조합원분양·보류지, 타입별 전용면적과 세대수를 담습니다. 면목역1구역은 총 442세대, 일반분양 계획 117세대, 주택형 13종입니다. 분양·임대 면적 구간까지만 공개한 번동에는 해당 구간을 표시합니다. 면목역1구역 상세
어디까지 왔나
대상지에서는 관리계획 승인고시일을, 개별 구역에서는 사업시행계획 인가일과 공개 단계를 확인합니다. 서울시가 집계한 사업구역 수와 이 지도에서 눌러 볼 수 있는 구역 수를 구분합니다.

다음 수집 순서

  1. 최근 변경 이력. 당초 고시와 변경 고시를 같은 구역에 연결해 어떤 날짜에 세대수·층수·시공계약이 어떻게 달라졌는지 보여줍니다.
  2. 주민이 참여할 일정. 구청 공람·의견제출 공고에서 접수 기간, 제출처와 원문을 수집합니다. 마감일이 지난 공고는 이력에 남깁니다.
  3. 분양·입주 일정. 입주자모집공고가 나오면 일반공급 세대수, 청약일과 공고상 입주 예정월을 연결합니다. 인가 당시의 일반분양 계획과 모집공고 물량은 각각 날짜를 붙입니다.

지도와 사업 소식

사업 소식은 발행일 순으로 정렬하며 공식 자료·언론 보도, 자치구, 서울 공통 정책으로 찾아볼 수 있습니다. 제목을 누르면 원문이 열리고 연결된 주소를 누르면 지도 상세로 이동합니다. 구역 상세에서 상위 대상지에 관한 소식은 적용 범위를 따로 표시합니다. 사업 소식 열기

모바일 지도와 패널

상세 패널의 ‘크게 보기’로 읽을 공간을 늘리고, 패널 제목을 누르면 접어서 지도를 넓힐 수 있습니다. 한글 구역명과 단계는 팝업에서 줄을 나누어 표시합니다. 320px·390px 모바일 폭에서 긴 이름의 줄바꿈과 가로 넘침을 점검합니다.

04 / DATA & DELIVERY

날짜별 정적 데이터 운영

웹은 배포된 정적 파일만 읽습니다. 데이터의 일자별 보관과 공개 화면의 최신 버전 선택을 분리해, 나중에 수집 방식을 바꿔도 지도 구조는 유지합니다. GitHub Pages 공식 문서

폴더 구조 제안

moatown-data/
├── latest.json
└── snapshots/
    └── YYYY-MM-DD/
        ├── towns.json
        ├── zones.json
        └── boundaries.geojson

각 파일의 역할

  • latest.json: 현재 공개 중인 스냅샷과 갱신일.
  • towns.json: 선정 대상지, 공식 상태, 위치·출처.
  • zones.json: 대상지에 연결되는 세부 구역과 항목별 근거.
  • boundaries.geojson: 확인된 모아타운·사업구역 경계. 각 데이터는 고정 ID로 연결.
출처 우선순위
서울시 공식 선정 발표 또는 공식 현황 자료로 포함 여부를 확인합니다. 구체적 경계·계획·사업 상태는 해당 지역의 서울시·자치구 고시, 공고 및 첨부자료를 우선 확인합니다. 문서 간 차이가 나면 적용 구역·문서의 효력·기준일을 검토하고, 해결되지 않으면 미확인으로 둡니다.
날짜 구분
한국시간 기준 날짜로 스냅샷을 관리합니다. 사이트 데이터 갱신일과 각 수치·경계의 공식 자료 기준일을 구분합니다. 공식 자료가 바뀌지 않았다면 최신 공식 발표가 나온 것처럼 표시하지 않습니다.
이번 갱신 방식
공식 원문 확인 → 날짜별 스냅샷 작성 → 대상지·구역 ID, 도형, 출처 검증 → 최신 포인터 갱신 및 배포. 검증에 실패하면 이전 정상 스냅샷을 유지합니다.
추후 자동화
cron 같은 배치는 나중에 도입합니다. 공개 소식 수집 결과는 먼저 검증하며, 소식만으로 공식 상태나 경계를 덮어쓰지 않습니다. 배포된 정적 데이터를 읽는 지도는 그대로 유지합니다.
05 / RELEASE CHECK

공개 전에 확인할 것

  • 서울시 공식 선정 목록과 데이터 포함 범위를 대조합니다. 확인이 덜 되었으면 누락을 숨기지 않고 자료 범위와 기준일을 표시합니다.
  • 대표 위치만 있는 대상지, 세부 구역이 없는 대상지, 계획안·확정 값이 섞인 구역에서도 잘못된 경계나 숫자를 보여주지 않습니다.
  • 지도와 목록의 필터가 일치하고, 모바일과 키보드 환경에서도 대상지를 선택하고 원문에 접근할 수 있습니다.
  • 배경지도·공간자료의 재사용 조건과 출처 표기를 확인합니다. 배경지도를 불러오지 못해도 목록과 구역 상세는 계속 볼 수 있게 합니다.
  • GitHub Pages 프로젝트 경로에서 데이터와 링크가 정상 동작하고, 최신 포인터가 존재하는 스냅샷을 가리키는지 확인합니다.
이번 버전에서 제외: 로그인·운영진 관리·필지별 동의 정보·전자동의·게시판·분담금 계산기·AI 기능·소식 수집 배치. 정적 공개 파일에는 주민 개인정보나 내부 자료를 넣지 않습니다.
